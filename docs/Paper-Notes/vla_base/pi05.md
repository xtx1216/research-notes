# π₀.₅：A Vision-Language-Action Model with Open-World Generalization

> Kevin Black et al., Physical Intelligence  
> 论文版本：arXiv:2504.16054v1（2025-04-22）

---

## 1. 这篇论文在解决什么问题

π₀ 已经证明了：把预训练 VLM、机器人数据、Flow Matching 和 Action Chunking 结合起来，可以得到一个比较强的通用机器人策略。

但 π₀ 主要回答的是：

> **一个大规模 VLA 能不能在很多机器人、很多任务上学到通用操作能力？**

π₀.₅ 进一步追问：

> **当机器人真正离开实验室，进入训练时从未见过的新家庭、新布局、新物体和长程任务时，VLA 能不能仍然工作？**

论文把这个问题称为：

\[
\boxed{\text{Open-World Generalization}}
\]

也就是不只要求：

- 换一个同类物体还能抓；
- 换一个背景还能执行；
- 换一个位置还能完成任务；

而是要求机器人进入**完全新的真实家庭环境**，面对新的厨房、卧室、物体、布局和任务组合，仍然能够完成 2–15 分钟的多阶段操作任务。

---

## 2. 整篇论文最核心的思想

π₀.₅ 的核心不是简单“把 π₀ 做大”，而是：

\[
\boxed{\text{让同一个 VLA 从大量异构数据源中共同学习}}
\]

作者认为，真正的 open-world generalization 不可能只靠：

\[
\text{更多目标机器人 demonstration}
\]

因为现实世界组合太多，不可能把所有：

- 房间；
- 物体；
- 布局；
- 任务；
- 异常情况；

全部通过机器人数据覆盖。

所以 π₀.₅ 的思路是让模型同时吸收：

1. **目标移动机器人数据**
2. **其他固定机械臂的数据**
3. **实验室跨机器人数据**
4. **高层子任务标注**
5. **人类语言指导**
6. **互联网图文 / VQA / 目标检测数据**

最终让这些知识迁移到：

\[
\boxed{\text{新家庭中的移动机器人操作}}
\]

论文特别强调：在第一阶段训练中，**97.6% 的训练样本并不是“移动机器人在家庭里做家务”这种目标域数据**。

这说明作者真正想证明的是：

> **机器人泛化能力可以来自跨任务、跨机器人、跨模态的数据迁移，而不是只靠目标域 demonstration 的暴力扩充。**

## 3. π₀.₅ 相比 π₀ 最大的变化

可以先用一张表记住：

|                         | π₀                       | π₀.₅                           |
| ----------------------- | ------------------------ | ------------------------------ |
| 主要目标                | 通用机器人控制           | Open-world 泛化                |
| Backbone                | PaliGemma VLM            | PaliGemma VLM                  |
| Action Expert           | 有                       | 有                             |
| 动作建模                | Flow Matching            | FAST + Flow Matching           |
| 预训练动作              | 连续 Flow                | **离散 FAST token**            |
| 后训练动作              | Flow Matching            | **连续 Flow Matching**         |
| 高层子任务预测          | 可外接 high-level policy | **模型内部直接预测**           |
| Web data co-training    | 不是重点                 | **核心组成**                   |
| 人类 verbal instruction | 无                       | **有**                         |
| 推理结构                | 低层 VLA                 | **高层 subtask → 低层 action** |
| 主要场景                | 多机器人、多任务         | **完全新家庭环境**             |

一句话：

\[
\boxed{
\pi_0:
\text{General Robot Control}
}
\]

\[
\boxed{
\pi_{0.5}:
\text{General Robot Control}
+
\text{Open-World Generalization}
}
\]

## 4. 整体框架

π₀.₅ 分成两个训练阶段：

```text
Internet-pretrained VLM
        ↓
Pre-training
        ↓
异构数据共同训练
        ↓
FAST 离散动作 + 文本 + 检测 + High-Level Subtask
        ↓
得到通用 VLA
        ↓
Post-training
        ↓
加入 Flow Matching Action Expert
        ↓
强化移动机器人 / 家庭任务能力
        ↓
Inference
        ↓
High-Level Subtask Prediction
        ↓
Low-Level Action Chunk
```

最重要的是：

\[
\boxed{
\text{Pre-training 负责“学广”}
}
\]

\[
\boxed{
\text{Post-training 负责“学精 + 实时控制”}
}
\]

## 5. 输入和输出是什么

π₀.₅ 输入 observation：

\[
o_t =
[I_t^1,\dots,I_t^n,q_t]
\]

其中：

- \(I_t^i\)：多摄像头 RGB 图像；
- \(q_t\)：机器人 proprioception；
- \(\ell\)：用户给出的高层任务指令。

例如：

> “put away the dishes”

模型同时建模：

\[
\pi_\theta(a_{t:t+H},\hat{\ell}\mid o_t,\ell)
\]

这里：

- \(\ell\)：总体任务，例如“收拾餐具”；
- \(\hat{\ell}\)：模型自己生成的当前子任务；
- \(a_{t:t+H}\)：连续动作 chunk。

作者把它分解成：

\[
\pi_\theta(a_{t:t+H},\hat{\ell}\mid o_t,\ell)
=
\pi_\theta(a_{t:t+H}\mid o_t,\hat{\ell})
\pi_\theta(\hat{\ell}\mid o_t,\ell)
\]

也就是：

### High-Level

\[
\pi_\theta(\hat{\ell}\mid o_t,\ell)
\]

决定：

> **下一步应该做什么？**

例如：

> pick up the plate

### Low-Level

\[
\pi_\theta(a_{t:t+H}\mid o_t,\hat{\ell})
\]

决定：

> **机械臂具体应该怎么动？**

---

## 6. 这是一个“统一模型”的层次化策略

很多机器人 hierarchical policy 是：

```text
VLM Planner
    ↓
Subtask
    ↓
Robot Policy
```

也就是：

\[
\text{两个模型}
\]

但 π₀.₅ 的特点是：

\[
\boxed{\text{同一个模型同时承担高层和低层}}
\]

推理过程：

```text
“clean the kitchen”
        ↓
π₀.₅ High-Level
        ↓
“pick up the plate”
        ↓
π₀.₅ Low-Level
        ↓
连续机器人动作
```

然后观察新状态：

```text
新的 Observation
        ↓
“put plate in sink”
        ↓
执行
        ↓
下一 Observation
```

因此它有一点类似：

\[
\text{Robot Chain-of-Thought}
\]

只是这个“CoT”不是长文本推理，而是：

\[
\boxed{\text{显式预测 semantic subtask}}
\]

---

## 7. 为什么需要 High-Level Subtask

如果直接：

\[
\text{“clean the kitchen”}
\rightarrow
\text{robot action}
\]

任务跨度可能达到几分钟甚至十几分钟。

对 low-level policy 来说，目标太抽象。

所以 π₀.₅ 先转成：

```text
clean kitchen
    ↓
open drawer
    ↓
pick up tong
    ↓
put tong into drawer
    ↓
close drawer
    ↓
pick up plate
    ↓
put plate into sink
```

这样长程任务被拆成了许多局部 skill。

因此：

\[
\boxed{
\text{High-Level负责任务结构}
}
\]

\[
\boxed{
\text{Low-Level负责动作执行}
}
\]

---

## 8. Pre-training 为什么使用 FAST，而不是直接 Flow Matching

这是 π₀.₅ 相比 π₀ 很重要的技术变化。

π₀ 主要用：

\[
\text{Flow Matching}
\]

建模连续 action chunk。

但 π₀.₅ 在大规模 pre-training 阶段改为：

\[
\boxed{\text{FAST 离散 Action Token}}
\]

原因是：

离散 token 可以直接把 robot action 转成：

\[
\text{next-token prediction}
\]

于是：

- 文本；
- action；
- bounding box；
- high-level subtask；

都可以统一成类似语言模型的训练形式。

优点：

\[
\boxed{\text{训练更简单、稳定，而且计算效率更高}}
\]

---

## 9. 但为什么后面又重新使用 Flow Matching

FAST 的缺点是：

推理时需要 autoregressive decoding。

也就是：

\[
x_1
\rightarrow
x_2
\rightarrow
x_3
\rightarrow
\dots
\]

如果 robot action chunk 很长：

\[
\text{Inference latency}
\]

会变大。

机器人需要高频实时控制，因此 π₀.₅ 在 post-training 中加入：

\[
\boxed{\text{Flow Matching Action Expert}}
\]

最终形成：

\[
\boxed{
\text{Pre-training: FAST}
}
\]

\[
\boxed{
\text{Post-training / Inference: Flow Matching}
}
\]

作者相当于想得到：

> **FAST 的训练效率 + Flow Matching 的动作精度和推理效率。**

---

## 10. FAST + Flow Matching 的联合训练

Post-training 阶段同时保留：

### 离散 token loss

\[
\mathcal L_{\text{token}}
\]

负责：

- language；
- high-level subtask；
- FAST action token；
- web multimodal task。

同时增加：

### Flow Matching loss

\[
\mathcal L_{\text{flow}}
\]

整体可以理解成：

\[
\mathcal L
=
\mathcal L_{\text{CE}}
+
\alpha \mathcal L_{\text{flow}}
\]

论文中：

\[
\alpha = 10
\]

这样模型同时保持：

\[
\text{text prediction}
\]

和：

\[
\text{continuous action generation}
\]

能力。

---

## 11. Flow Matching 部分

连续动作加入噪声：

\[
a_{t:t+H}^{\tau,\omega}
=
\tau a_{t:t+H}
+
(1-\tau)\omega
\]

其中：

\[
\omega\sim\mathcal N(0,I)
\]

模型学习 vector field。

推理阶段从 noise 开始：

\[
a^0\sim\mathcal N(0,I)
\]

不断通过 Action Expert 去噪。

论文最终使用：

\[
10
\]

次 denoising step 来生成连续动作 chunk。

所以低层策略不是：

\[
\text{逐 action token 自回归输出}
\]

而是：

\[
\boxed{
\text{一次生成一段连续动作}
}
\]

---

## 12. Action Expert

π₀.₅ 延续 π₀ 的设计：

```text
VLM Backbone
      +
Action Expert
```

VLM Backbone 处理：

- image；
- language；
- high-level semantic information。

Action Expert 专门负责：

\[
\text{continuous robot actions}
\]

参数规模约：

\[
300M
\]

而 VLM 侧继承 PaliGemma。

这种设计可以理解成：

> **语义推理和动作生成共享 Transformer 信息，但动作生成拥有自己的专门参数。**

---

## 13. 为什么 Action Expert 有意义

机器人动作和语言 token 的性质差别非常大。

文本：

\[
\text{discrete}
\]

机器人动作：

\[
\text{continuous}
\]

而且要求：

- 高频；
- 精确；
- 平滑；
- 时序连续。

所以作者没有强迫：

\[
\text{Language Head}
\]

同时承担所有 continuous control。

而是：

\[
\boxed{
\text{VLM负责理解}
+
\text{Action Expert负责控制}
}
\]

---

## 14. π₀.₅ 真正最大的创新：Heterogeneous Co-training

论文最核心的训练数据可以分成五类：

\[
\boxed{
MM + ME + CE + HL + WD
}
\]

Post-training 再加入：

\[
\boxed{VI}
\]

分别是：

| 缩写 | 数据                               |
| ---- | ---------------------------------- |
| MM   | Mobile Manipulator                 |
| ME   | Multi-Environment non-mobile robot |
| CE   | Cross-Embodiment laboratory data   |
| HL   | High-Level subtask prediction      |
| WD   | Web Data                           |
| VI   | Verbal Instruction                 |

这六种数据一起构成 π₀.₅ 最重要的能力来源。

---

## 15. MM：移动机器人家庭数据

MM 是：

\[
\text{Diverse Mobile Manipulator Data}
\]

约：

\[
400\text{ hours}
\]

覆盖：

\[
\sim100
\]

个不同真实家庭环境。

任务例如：

- shirt in basket；
- spatula in holder；
- dish in sink；
- make bed；
- item in drawer；
- wipe plate。

这是和最终测试最直接相关的数据。

但是论文非常强调：

> **它并不是全部数据，甚至不是绝大多数训练样本。**

---

## 16. ME：不同家庭中的固定机械臂数据

ME：

\[
\text{Multi-Environment non-mobile robot}
\]

使用：

- 单臂；
- 双臂；
- fixed-base robot。

虽然 embodiment 和最终 mobile manipulator 不一样，

但是它们更轻、更容易搬运，因此可以进入更多家庭采集数据。

这带来：

\[
\boxed{\text{环境多样性}}
\]

也就是说：

> 即使机器人身体不同，只要操作知识有共性，也可以迁移。

---

## 17. CE：实验室 Cross-Embodiment Data

CE 是实验室里的大规模跨 embodiment 数据。

包括：

- 单臂；
- 双臂；
- 静态机器人；
- 移动机器人；
- OXE 数据。

任务包括：

- table bussing；
- shirt folding；
- bottle packing；
- drawer sorting；
- coffee grinding 等。

有些任务和最终目标很相关，

有些则几乎无关。

作者就是要测试：

\[
\boxed{\text{不同机器人、不同任务的数据是否能产生正迁移}}
\]

实验表明：**能，而且非常重要。**

---

## 18. HL：High-Level Subtask Prediction

作者给 multi-stage robot trajectory 人工标注：

\[
\text{semantic subtask}
\]

例如整体任务：

> clean the bedroom

当前 observation 下的 subtask：

> pick up pillow

或者：

> adjust blanket

训练时让模型同时预测：

\[
\text{subtask label}
\]

以及：

\[
\text{action}
\]

于是模型自然变成：

\[
\boxed{
\text{High-Level Policy}
+
\text{Low-Level Policy}
}
\]

---

## 19. Bounding Box 也是高层训练的一部分

在预测 subtask 前，作者还标注：

\[
\text{relevant object bounding boxes}
\]

例如：

```text
closet → bounding box
mitten → bounding box
drawer → bounding box
```

所以 high-level reasoning 实际上包含：

\[
\text{Scene Understanding}
\rightarrow
\text{Object Grounding}
\rightarrow
\text{Subtask Prediction}
\]

这使 high-level policy 不只是“语言生成”，而是明显和当前视觉环境绑定。

## 20. WD：Multimodal Web Data

作者继续使用 web-scale multimodal data，包括：

### Image Captioning

例如：

\[
\text{image}\rightarrow\text{caption}
\]

### VQA

例如：

> What kind of pie is this?

### Object Localization

例如：

\[
\text{object}
\rightarrow
\text{bounding box}
\]

数据来源包括：

- COCO；
- CapsFusion；
- Cambrian-7M；
- PixMo；
- VQAv2；
- 额外 household object localization 数据。

它们并不是机器人动作数据。

但是后面的消融证明：

\[
\boxed{\text{Web data 对 OOD object 和 High-Level reasoning 很重要}}
\]

---

## 21. VI：Verbal Instruction Data

Post-training 中又加入一种非常有意思的数据：

\[
\boxed{\text{Verbal Instruction}}
\]

不是人类直接遥操作 robot joint。

而是：

> 人类站在旁边，通过语言告诉机器人下一步应该做什么。

例如：

```text
Human:
“put cup in sink”
```

low-level policy 自己执行。

人类只负责：

\[
\text{选择正确 subtask}
\]

因此这种数据其实是在给：

\[
\boxed{\text{High-Level Policy做 demonstration}}
\]

可以理解成：

\[
\text{Language Teleoperation}
\]

---

## 22. 这种 Verbal Instruction 为什么重要

普通 teleoperation 教：

\[
\text{怎么动}
\]

而 VI 教：

\[
\text{现在应该做什么}
\]

对应：

\[
\boxed{
\text{Low-Level skill}
\quad vs\quad
\text{High-Level decision}
}
\]

论文发现：

虽然 VI 在 high-level mobile manipulation examples 中只占比较小的一部分，

但去掉 VI 后性能明显下降。

说明：

> **少量高质量“决策示范”可以显著提升长程任务能力。**

## 23. Pre-training 数据流程

Pre-training 阶段使用：

\[
MM + ME + CE + HL + WD
\]

全部采用：

\[
\boxed{\text{discrete token}}
\]

方式。

包括 robot action，也先经过：

\[
\text{FAST tokenizer}
\]

转换成 token。

训练变成统一的：

\[
\text{Next Token Prediction}
\]

因此同一个模型可以同时训练：

```text
Image → Caption
Image → Answer
Image → Bounding Box
Robot Observation → Subtask
Robot Observation → Action Token
```

这就是 π₀.₅ co-training 最核心的统一机制。

---

## 24. Post-training 数据流程

Pre-training：

\[
280k
\]

gradient steps。

随后 Post-training：

\[
80k
\]

steps。

Post-training 主要目的：

### 1. 专门适配 Mobile Manipulation

数据聚焦：

\[
MM + ME
\]

而不再强调 laboratory CE。

### 2. 加入 Action Expert

开始训练：

\[
\text{Flow Matching}
\]

### 3. 保持 semantic 能力

继续加入：

\[
WD + HL
\]

### 4. 加入 High-Level supervision

加入：

\[
VI
\]

所以 Post-training 可以理解成：

\[
\boxed{
\text{把一个很广的VLA}
\rightarrow
\text{变成真正能在家庭里实时工作的机器人策略}
}
\]

机器人拥有：

- 2 × 6-DoF arm；
- 2 × gripper；
- holonomic base；
- torso lift；
- 4 个 RGB camera。

总 state/action dimension：

\[
18\sim19
\]

摄像头包括：

- left wrist；
- right wrist；
- front camera；
- rear camera。

High-Level inference 使用：

\[
4\text{ cameras}
\]

Low-Level inference 使用：

- wrist camera；
- front camera。

## 26. 控制频率

π₀.₅ 直接控制：

- arm target pose；
- gripper；
- torso；
- base velocity。

控制频率：

\[
50\text{ Hz}
\]

并使用：

\[
\text{Action Chunking}
\]

底层只使用简单 PD controller。

没有额外：

- trajectory planner；
- collision planner；
- model-based navigation stack。

因此作者强调：

\[
\boxed{\text{Manipulation + Navigation 基本是 end-to-end learned}}
\]

## 27. 实验到底想回答什么

论文主要研究五个问题：

1. π₀.₅ 能不能在**完全新的真实家庭**完成复杂任务？
2. 训练环境数量增加后，泛化能力如何变化？
3. 各种 co-training 数据到底有没有用？
4. π₀.₅ 相比 π₀ 是否真的更强？
5. High-Level inference 到底有没有必要？

## 28. Real Home Evaluation

最终评测放在：

\[
\boxed{\text{训练中完全没出现过的真实家庭}}
\]

环境包括：

- 新厨房；
- 新卧室；
- 新物体；
- 新背景；
- 新布局。

测试任务例如：

### Kitchen

- items in drawer；
- dishes in sink。

### Bedroom

- laundry in basket；
- make bed。

这些都不只是一次 pick-and-place。

很多 episode 持续：

\[
2\sim5\text{ minutes}
\]

更完整的清理任务可以持续：

\[
10\sim15\text{ minutes}
\]

## 29. Real Home 的真正难点

以：

> put the items in the drawer

为例。

模型需要自己产生：

```text
pull out drawer
       ↓
pick up tong
       ↓
put tong into drawer
       ↓
pick next item
       ↓
put item into drawer
       ↓
push drawer
```

人类只提供：

\[
\text{总体目标}
\]

中间的：

\[
\hat{\ell}_1,\hat{\ell}_2,\dots
\]

由 π₀.₅ 自己决定。

所以这个实验同时测试：

\[
\text{Perception}
+
\text{Semantic Reasoning}
+
\text{Planning}
+
\text{Navigation}
+
\text{Manipulation}
\]

## 30. 环境数量与 Generalization

作者把训练环境数量从：

\[
3
\]

逐渐增加到：

\[
12,22,53,82,104
\]

然后在完全新的 mock homes 上测试。

结果非常清楚：

\[
\boxed{

## 34. 为什么 Cross-Embodiment 有效

虽然 robot embodiment 不同：

\[

\]

但很多更高层的 manipulation structure 是共享的。

例如：

```text

→ grasp
→ lift
→ transport
→ insert/place
```

所以模型可以从其他机器人中学习：

\[
\text{Manipulation Prior}
\]

然后再映射到：

\[
\text{目标 embodiment action}
\]

这也是 generalist VLA 的重要优势。

\]

例如帮助模型知道：

- 什么是 pill bottle；

## 41. 为什么 GPT-4 High-Level 反而不够好

作者测试：

核心原因可以理解为：

GPT-4 虽然语义知识强，

但它没有直接在：

\[
\text{robot action distribution}
\]

上被训练。

所以它给出的 subtask：

\[
\text{语义上可能合理}
\]

但未必是：

\[
\boxed{
\text{当前 low-level policy 最容易执行的 subtask}
}
\]

而 π₀.₅ 的 High-Level 和 Low-Level 来自同一个训练体系。

因此二者更加：

\[

\]

## 42. Human HL 也没有超过完整 π₀.₅

\]

更合理的理解是：

人类认为合理的下一步：

\[
\text{不一定是当前 robot policy 最擅长的下一步}
\]

因此 high-level policy 和 low-level policy 的：

\[
\boxed{\text{alignment}}
\]

非常重要。

## 46. 这篇论文最大的局限

作者自己列出了几个明显问题。

### 1. 依然会因为新物理结构失败

例如：

- 陌生 drawer handle；
- cabinet 太难打开。

这说明 semantic understanding 并不能自动解决：

\[
\text{unseen physical dynamics}
\]

---

### 2. Partial Observability

例如：

机器人 arm 挡住 spill。

于是：

\[
\text{camera看不到目标}
\]

模型可能忘记：

> 这里还有东西需要擦。

说明当前策略缺少长期：

\[
\boxed{\text{Memory}}
\]

---

### 3. High-Level Policy 会“走神”

例如：

```text
open drawer
→ close drawer
→ open drawer
→ ...
```

说明虽然有 explicit subtask，

但还没有稳定的：

\[
\text{long-term task state}
\]

---

### 4. Prompt 仍然比较简单

模型处理的主要还是：

> clean bedroom

> put dishes in sink

还没有系统解决：

> 把红色杯子洗完后放到左边第二个柜子，如果柜子满了就放到架子上。

这种复杂 preference / conditional instruction。

## 47. Memory 是非常明显的后续方向

当前 π₀.₅ inference 基本依赖：

\[
o_t
\]

当前 observation。

但长程任务真正需要：

\[
h_t =
f(o_{1:t},a_{1:t-1})
\]

即：

\[
\boxed{\text{历史状态 / Episodic Memory}}
\]

例如：

- 哪个 drawer 已经清理了；
- 哪件衣服已经放进 basket；
- 哪个房间已经完成；
- 物品之前放在哪里。

作者自己也明确指出：

> 更丰富 context 和 memory 可能显著提升跨房间、强 partial observability 的任务。
